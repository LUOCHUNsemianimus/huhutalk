# 2026-10-27：Forge 1.20.1 独立移植工作日志

- **日期**：2026-10-27（北京时间）
- **基线**：从 `b7605a8` 建立独立分支 `port/forge-1.20.1` 的 Forge 1.20.1 工作树。
- **目的**：将 HuhuTalk 从 NeoForge 1.21.1 移植为 Minecraft 1.20.1 / Forge 47.4.16 / Java 17 /
  车万女仆 1.5.3 Forge 的可运行候选版；原 Neo 工程与用户原 pianchang 实例保持不动。
- **状态**：用户于 2026-10-27 确认正常使用场景的功能逻辑验收通过，准备发布 `1.1.0-forge1.20.1`。

## 改动区域、目的与关联边界

| 区域 | 主要改动 | 目的 |
| --- | --- | --- |
| 网络传输 | 项目自有 own transport 适配层，底层 Forge `SimpleChannel`；24 KB 分片、2 MiB 完整负载重组、30 秒回收，明确处理缺片/乱序/冲突 | 在不降低 1 MB 图片能力的前提下适配 Forge 1.20.1 包大小与通道语义 |
| Java 17 与旧数据 | Java 17 toolchain/`--release 17`；旧 NBT 读写、注册表与资源路径适配（`pack_format=15`、1.20.1 配方/loot/tag 目录） | 让 1.21.1 继承源码与资源能在 1.20.1 正确加载 |
| 事件与 tick | `ServerTickEvent`/`ClientTickEvent` 改用 Forge 的 END 阶段；登出/停服清理重组缓冲 | 对齐 Forge 事件阶段，避免重复或过早处理 |
| 客户端渲染 | 模型屏 FBO 的 PoseStack 处理与相机状态恢复；自拍/后摄渲染路径适配 | 保持原有屏幕与相机效果，减少状态泄漏 |
| 救援 | 救援逻辑改接原生桥接，复活点为死亡维度/死亡坐标，同时保留原床位登记 | 让真死救援在 1.20.1 下于死亡点按死亡视角复活，且不丢失原床位记录 |
| 女仆交互 | `forceTick` 的 add/remove 使用相同的 `true` 参数 | 修正 1.20.1 API 下的配对语义 |
| 双端分离 | common 入口不引用 `ClientPayloadSetup`；客户端类由该类自身以 `Dist.CLIENT`/`MOD` 订阅者在 `FMLClientSetupEvent.enqueueWork` 中注册；专用服不加载客户端网络类，音效在 common 门控后委托客户端 helper | 避免专用服启动时因客户端类崩溃 |
| 构建环境 | 在 JVM 参数中提前启用 TLS 1.2，保持证书校验开启 | 解决 Forge/Maven 仓库握手问题，不关闭安全校验 |
| 验证设施 | 独立 `gametest` 源集、3 个原生 GameTest、仅在 `-PportSmoke` 时启用的客户端 smoke 驱动 | 在不污染正式 jar 的前提下验证真实物品/配方与客户端界面 |
